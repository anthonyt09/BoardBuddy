# BoardBuddy iOS

Native iOS app that extracts pose landmarks from a skate clip using Google
ML Kit's on-device Pose Detection, then lets you label the trick (name,
good/bad, notes). This is now the primary pose-extraction + labeling
pipeline for BoardBuddy — see the note in the root [README](../../README.md)
and [docs/RECREATION_PLAN.md](../../docs/RECREATION_PLAN.md).

## Why ML Kit instead of MediaPipe here

The original pipeline (`ml/boardbuddy_ml/pose.py`) ran MediaPipe Pose in
Python, server-side. This app follows Google's ["Detect poses with ML Kit"
iOS guide](https://developers.google.com/ml-kit/vision/pose-detection/ios)
instead: pose detection runs on-device, in Swift, as part of the same app
you use to review and label clips — no round trip to a server just to see
where a trick broke down.

## Setup

Requires Xcode (full install, not just Command Line Tools) and Homebrew.

```bash
# One-time tooling (XcodeGen generates the .xcodeproj from project.yml;
# CocoaPods pulls in GoogleMLKit/PoseDetectionAccurate, which has no SPM
# distribution as of this writing)
brew install xcodegen cocoapods

cd apps/ios
xcodegen generate
pod install

open BoardBuddy.xcworkspace
```

Build and run on a **simulator or device running iOS 16+** (ML Kit's Pose
Detection needs 15.5+; `PhotosPicker` for the import flow needs 16+). The first
launch will ask for photo library access (`NSPhotoLibraryUsageDescription`)
so it can read a video you pick.

Both `BoardBuddy.xcodeproj` and `BoardBuddy.xcworkspace` are gitignored —
they're fully regenerated by `xcodegen generate` + `pod install` from
`project.yml` and `Podfile`. Re-run those two commands any time you pull
changes that touch either file.

## How it works

1. **Import** — pick a video from the photo library (`ImportVideoView`).
2. **Extract** — `VideoPoseExtractor` decodes every frame with
   `AVAssetReader` and runs `PoseDetectorService` (ML Kit, `.singleImage`
   mode) on each one. ML Kit's `.stream` mode is for live camera input with
   temporal smoothing across a feed; since we're processing a finished file
   frame-by-frame, each frame is detected independently.
3. **Store** — `ClipStore` saves the result as a new unlabeled clip.
4. **Label** — on `LabelClipView`, enter the trick name, mark it good or
   bad, and add notes on what made it so. Labels can be added or edited at
   any time after extraction, independent of it.

## Data model

```
ClipMetadata      — one per clip, catalog-weight (no landmarks)
├── id, sourceFilename, createdAt
├── fps, frameWidth, frameHeight, frameCount, detectedFrameCount
└── label: TrickLabel?
    ├── trickName          e.g. "kickflip"
    ├── quality            .good | .bad
    ├── notes              free text — why it was good/bad
    └── labeledAt

PoseFrame         — one per video frame, heavy (33 landmarks each)
├── frameIndex, timestamp
└── landmarks: [LandmarkSample]
    ├── name                LandmarkName (ML-Kit's 33 BlazePose points)
    ├── x, y                pixel coords in the source frame
    ├── z                   ML Kit's rough hip-relative depth
    └── likelihood          0...1 "in frame" confidence
```

`ClipMetadata` and `PoseFrame` are stored separately on disk
(`ClipStore.swift`) for the same reason `ml/data/labels.jsonl` and
`ml/data/processed/` were split in the Python pipeline: you want to be able
to scan the catalog (filter by trick, by quality, by detection rate) without
loading every frame of every clip. A frame with no detected person has an
empty `landmarks` array — treat that as missing data, not a zero pose.

On-disk layout, under the app's Documents directory:

```
BoardBuddyClips/
├── clips.jsonl              # one ClipMetadata JSON object per line
└── frames/
    └── <clip-uuid>.json     # that clip's [PoseFrame]
```

`clips.jsonl` uses the same one-JSON-object-per-line convention as
`ml/data/labels.jsonl` so it's easy to point a future training script at
either. To pull it off a simulator for inspection:

```bash
xcrun simctl get_app_container booted com.anthonytaboada.boardbuddy.BoardBuddy data
# -> prints the container path; clips.jsonl is under Documents/BoardBuddyClips/
```

## Project layout

```
apps/ios/
├── project.yml              # XcodeGen spec — source of truth for the target
├── Podfile                  # GoogleMLKit/PoseDetectionAccurate
└── BoardBuddy/
    ├── Sources/BoardBuddy/
    │   ├── App/              # @main entry point
    │   ├── Models/           # LandmarkName, PoseFrame, TrickLabel, ClipMetadata
    │   ├── Pose/             # PoseDetectorService, VideoPoseExtractor, ML Kit mapping
    │   ├── Storage/          # ClipStore (clips.jsonl + per-clip frame files)
    │   └── Views/            # ClipListView, ImportVideoView, LabelClipView
    └── Resources/            # Info.plist (generated by xcodegen)
```
